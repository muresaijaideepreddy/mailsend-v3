## Account and workspace behavior

The app supports separate workspaces, with one executive account and multiple assistant accounts per workspace. It does not implement a global one-executive limit or a one-simultaneous-login rule. The database relationship/constraints and workspace authorization tests support this model; neither PDF requires a single workspace for the whole app.

New executive Google signup and the management command provision an initial worker username; opening Worker settings also provisions one for an older workspace that has no assistants. Existing assistants are preserved. The executive sets the worker's password; no email is collected. Assistants use username/password only. Google callbacks reject existing assistant identities and emails or usernames matching a local account, so an email-shaped worker username cannot silently become an executive. An unrelated Google identity remains eligible for a separate executive workspace after successful Gmail consent; without an identity association the app cannot infer that this person is a worker. No executive account is created during the first identity step.
