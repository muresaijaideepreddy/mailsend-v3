## Account and workspace behavior

The app supports separate workspaces, with one executive account and multiple assistant accounts per workspace. It does not implement a global one-executive limit or a one-simultaneous-login rule. The database relationship/constraints and workspace authorization tests support this model; neither PDF requires a single workspace for the whole app.

New executive Google signup and the management command provision an initial worker username; opening Worker settings also provisions one for an older workspace that has no assistants. Existing assistants are preserved. The executive sets the worker's password and, for Google linking, its real email in Worker settings. The assistant can then log in locally, explicitly link the Google account matching that email, and use the shared Google button subsequently. An anonymous matching email cannot silently take over a local worker account. An unknown Google identity can create an executive workspace only after a separate successful Gmail grant for that same identity; no account is created during the first identity step. Assistant linking requires no Gmail access and cannot change the assistant role.
